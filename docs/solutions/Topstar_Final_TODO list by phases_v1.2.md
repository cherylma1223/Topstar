# Topstar 开发计划最终版 (Finalized v1.2)

日期：2026-05-02
说明：由 v1.1 版本升级，整合 Phase 2 意图识别层重构设计 (intent_design_v2.md)。

---

### 📅 Phase 1：核心大脑与真实教程落地 (1-2 周)
**目标**：实现真实的视频教程推荐，建立结构化协议，彻底解决“模型瞎编链接”的问题。

*   **[数据层]**
    *   [ ] **P1-D1** 创建 `tutorial_videos` 表 (SQLite WAL 模式)，包含质量分、状态机及点击统计字段。
    *   [ ] **P1-D2** 编写清洗脚本 `normalize_tutorials.ts`：将原始数据转化为标准 JSON。
    *   [ ] **P1-D3** 编写冷启动脚本 `bootstrap_quality_scores.ts`：实现基于标题、标签、收藏度的初始评分。
*   **[后端逻辑]**
    *   [ ] **P1-S1** 实现教程库加载与内存倒排索引，提升检索效率。
    *   [ ] **P1-S2** 实现 `recommendTutorials` 算法：支持“相关性召回 + 质量分排序 + 死链过滤”。
    *   [ ] **P1-S3** **[安全]** 实现意图路由 `intentRouter`：增加合规拦截逻辑（敏感词过滤）。
    *   [ ] **P1-S4** 创建 `intent_eval_set.jsonl`：包含 50 条测试用例，用于校准模型识别准确率。
    *   [ ] **P1-S5** 知识库模块化：实现动作、战术、器材知识的 Markdown 检索与输出模板校验。
*   **[API 与 运维]**
    *   [ ] **P1-S6** 新增 `POST /api/v2/chat`：返回包含 `answerText` 和 `tutorialVideos[]` 的结构化 JSON。
    *   [ ] **P1-S7** 实现 `link-health-check` 定期任务：凌晨自动探测链接存活，支持随机 jitter 防屏蔽。
    *   [ ] **P1-S8** **[内容安全]** 实现 `【核心秘诀】` 服务端脱敏：确保非 VIP 用户无法通过接口获取加密内容。
*   **[前端适配]**
    *   [x] **P1-F1** 接入 v2 接口，将报告卡片中的视频链接改为后端返回的真实数据。
    *   [ ] **P1-F2** **[UI 优化]** 实现统一化专家建议卡片：将文本回复与视频推荐聚合展示，并彻底清洗冗余 Markdown 符号。
        *   [ ] **P1-F2.1** 增强 `TypewriterText`：语义化剔除 `**`, `###` 等符号，仅保留 `【标题】`。
        *   [ ] **P1-F2.2** 升级 `AnalysisReportCard`：支持 `summaryText` 顶部注入，并优化“技术问题”等标题的高度自适应与空数据隐藏。
        *   [ ] **P1-F2.3** **[VIP 交互]** 实现专家建议卡片内的 VIP 锁定区块：包含点击跳转升级、内容防复制及 TTS 朗读绕过逻辑。
    *   [x] **P1-F3** **[文档]** 更新技术设计文档至 v1.4 (codex_v5)，明确 UI 聚合规范及 VIP 安全隔离逻辑。

**🚩 里程碑**：问“反手拧拉怎么练”，系统能秒回真实的教学视频，且死链不再出现。

#### 📅 Phase 2-A：视频分析任务化 (1-2 周)
**目标**：消灭前端假 mock，建立可靠的异步任务处理流程。

*   **[任务状态机]**
    *   [ ] **P2-D1** 创建 `analysis_jobs` 表：记录任务状态 (queued/running/done/failed)。
    - [ ] **P2-S1** 实现 `AnalysisWorker`：后台扫描 SQLite 任务队列，支持服务重启后的任务恢复。
    - [ ] **P2-S2** 实现阶段 A 处理器：基于用户文字描述生成结构化诊断报告（不涉及视频流）。
*   **[反馈与监控]**
    *   [ ] **P2-S3** 实现“链接失效”上报接口与“教程点击/曝光”埋点记录。
    *   [ ] **P2-S4** 新增任务查询接口 `GET /api/v2/analysis/jobs/{id}`。
*   **[前端交互重构]**
    *   [ ] **P2-F1** **[诚实设计]** 将视频上传界面改为“结构化描述表单”，告知用户当前为文字分析阶段。
    *   [ ] **P2-F2** 实现任务状态轮询：展示进度条，完成后渲染报告卡片。
    *   [ ] **P2-F3** 增加“链接失效？”反馈按钮，实现数据闭环。

**🚩 里程碑**：告别 `setTimeout` 假报告，系统拥有了真实的、可追踪的异步处理能力。

#### 📅 Phase 2-B：意图识别层重构 (1-2 周)
**目标**：把当前“主题分类式”的意图识别，升级为“请求理解式”的编排入口，解决教程请求、器材咨询、动作指导等场景中的误判、过度讲解与错误渲染问题。

*   **[意图识别协议重构]**
    *   [ ] **P2-I1** **[Schema]** 扩充识别协议：新增 `domain_intent`, `task_intent`, `response_mode` 及增强型 `entities`。
    *   [ ] **P2-I2** **[Logic]** 升级识别流程：实现 Stage A 规则预判、Stage B LLM 结构化理解及 Stage C Policy 修正层。
    *   [ ] **P2-I3** **[Policy]** 实现硬核 Policy 层：将业务策略（如“只要视频”）从 Prompt 剥离到代码中，提升稳定性。
    *   [ ] **P2-I4** **[Eval]** 创建 `intent_eval_set_phase2.jsonl`：包含 50+ 教程/器材/动作/边界模糊样本，进行回归测试。
*   **[场景适配与清理]**
    *   [ ] **P2-S5** 场景协议适配：支持 `RESOURCE_ONLY` (只要视频) 模式，细化器材/动作场景识别与分流。
    *   [ ] **P2-S6** 降级策略重做：实现“保守输出”与“最小损害渲染”，避免低置信度误判。
    *   [ ] **P2-S7** **[清理]** 移除旧版单层 Intent 依赖，清理冗余代码与模板逻辑。
*   **[前端适配]**
    *   [ ] **P2-F4** **[渲染适配]** 根据 `response_mode` 自动选择卡片类型（教程列表/报告卡/对比卡），消除猜测渲染。

**🚩 里程碑**：问“反手拧拉视频”不再出现冗余讲解，系统具备了稳定的结构化请求理解能力。

#### 📅 Phase 3：深度视频理解与持续优化 (持续迭代)
**目标**：让系统真正“看懂”视频，并优化长期运行成本。

*   **[深度分析 - 阶段 B]**
    *   [ ] **P3-S1** **[成本控制]** 前后端增加视频时长硬校验 (≤ 120s)，防止 token 过度消耗。
    *   [ ] **P3-S2** 接入 Gemini Files API：实现真实的视频帧分析。
    *   [ ] **P3-S3** 升级报告逻辑：在诊断中加入精准的时间戳 (如 `00:15 重心太高`)。
*   **[架构升级]**
    *   [ ] **P3-D1** 数据库迁移：从 SQLite 迁移至 PostgreSQL，支撑更复杂的数据统计与并发。
    *   [ ] **P3-S4** 实现“点击率自动调权”Job：根据真实点击数据动态优化 `quality_score`。
*   **[体验增强]**
    *   [ ] **P3-S5** 引入 Embedding 语义检索：提升“霸王拧”等口语化搜索的匹配度。
    *   [ ] **P3-F1** 小程序 UI 适配：复用 v2 接口完成端到端落地。

**🚩 里程碑**：用户上传 20 秒练球视频，系统在 1 分钟内给出带时间戳的精准教练反馈。
