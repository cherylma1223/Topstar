## 一、介绍背景技术，并描述已有的与本发明最相近似的现有技术方案

### 1.1 通用视频推荐系统

- **基于协同过滤的推荐**：如 YouTube 的推荐算法，基于用户观看历史和相似用户的行为模式进行推荐。此类方法需要大量用户行为数据，不适用于用户量较少的垂直领域应用。
- **基于内容的推荐**：通过视频的元数据（标题、描述、标签）进行相似性匹配推荐。此类方法不涉及领域专业语义，匹配精度有限。

### 1.2 教育领域推荐

- **MOOC 平台课程推荐**：如 Coursera、edX 等在线教育平台的课程推荐系统，基于学习者画像和课程元数据进行匹配，但未针对体育动作的专业语义进行优化。
- **运动教学视频搜索**：用户通过关键词在 YouTube、Bilibili 等平台搜索教学视频，依赖平台通用搜索引擎的排序，无法根据用户的具体技术问题进行精准推荐。

### 1.3 链接管理

- 现有的链接管理工具（如 Dead Link Checker）可以检测网页中的失效链接，但通常是一次性检测，不与内容推荐系统联动。

---

## 二、现有技术的缺点是什么（客观评价）？

1. **推荐与用户具体问题脱节**：通用推荐系统基于用户画像或行为历史推荐，无法根据用户在对话中描述的具体技术问题（如"反手拉球时手腕打不开"）推荐针对性的教学视频。

2. **缺乏领域专业语义匹配**：通用搜索引擎的关键词匹配不理解体育动作的专业术语和别名映射（如"反手拧拉"="反手台内拧""ChiQuita 技术"），导致召回率低。

3. **推荐结果无质量感知**：现有系统不区分教学视频的质量高低，可能推荐低质量的教学视频（如画质差、讲解不清、内容过时的视频）。

4. **推荐链接可能失效**：视频教程的 URL 可能因原作者删除、平台下架等原因失效，现有推荐系统通常不感知链接的可访问性状态，可能推荐用户无法打开的失效链接。

5. **推荐触发方式单一**：现有系统通常需要用户主动搜索教程，无法在对话交流或视频分析过程中自动触发推荐。

---

## 三、本发明解决的技术问题或技术目的？

1. **基于技术动作语义的精准推荐**：通过动作标识（action_id）精确匹配、标签语义匹配和标题关键词匹配三种召回信号，实现基于体育专业语义的教程视频精准推荐。

2. **多维度加权评分排序**：综合相关性、可用性和质量三个维度对候选教程进行加权评分和排序，确保推荐结果既相关又可用且高质量。

3. **链接健康感知**：通过定时链接健康检查，感知教程视频链接的可访问性状态，将链接状态纳入推荐排序因子，避免推荐失效链接。

4. **双通道自动触发**：在对话和视频分析两个场景中自动触发教程推荐，无需用户主动搜索。

## 四、本发明技术方案的详细阐述

### 4.1 教程视频数据模型

每个教程视频记录包含以下字段：
- **基本信息**：标题（title）、视频 URL（url）、平台来源（platform）
- **语义标签**：标签列表（tags）、关联动作标识（action_id）、关联战术标识（tactic_id）
- **质量指标**：质量评分（quality_score，0～10）
- **可用性状态**：链接健康状态（link_status：active / suspect / dead）、最后检查时间（last_checked）

### 4.2 多信号源候选召回

从教程视频数据库中，通过以下三种独立信号源并行召回候选教程：

1. **action_id 精确匹配**：若当前请求包含已识别的动作标识（如 `fh_loop`），则召回所有 action_id 字段匹配的教程视频
2. **tag 语义匹配**：将搜索标签列表（从用户消息和知识库命中条目中提取）与教程视频的标签列表进行交集匹配，召回包含匹配标签的教程视频
3. **标题关键词匹配**：将搜索标签中的关键词与教程视频标题进行模糊匹配，召回标题中包含关键词的教程视频

三种信号源的召回结果取并集，去重后进入评分排序阶段。

### 4.3 多维度加权评分 Rerank

对每个候选教程视频按以下维度进行加权评分：

**维度一：相关性基础分**

| 匹配类型 | 分值 | 说明 |
|----------|------|------|
| action_id 精确匹配 | +5 分 | 最强的语义关联信号 |
| tag 命中 | +2 分（上限） | 每命中一个 tag +1 分，最多 +2 分 |
| 标题关键词命中 | +0.5 分 | 最弱的模糊匹配信号 |

**维度二：可用性加分**

| 链接状态 | 分值 | 说明 |
|----------|------|------|
| active | +1 分 | 链接已验证可访问 |
| suspect | +0 分 | 链接状态可疑，不加分也不减分 |
| dead | 不召回 | 已确认失效的链接不参与推荐 |

**维度三：质量修正**

- quality_score × 0.3 作为 rerank 修正项
- 例如：quality_score = 8 → 额外加 2.4 分

最终排序分 = 相关性基础分 + 可用性加分 + 质量修正分

### 4.4 链接健康检查机制

通过定时后台任务（每日凌晨 3:00 执行）自动检测教程视频链接的可访问性：

1. 遍历数据库中所有教程视频记录
2. 对每个 URL 发起 HTTP HEAD 请求（带超时控制）
3. 根据响应状态码更新链接健康状态：
   - HTTP 200 → active
   - HTTP 403/404/500 或超时 → suspect（首次）→ dead（连续多次）
4. 更新最后检查时间戳

### 4.5 对话上下文联动触发

在智能对话编排流程中，当意图分类结果为以下类型时，自动触发教程推荐：
- 主意图为 TUTORIAL_REQUEST（用户明确请求教程）
- 主意图为 ACTION_COACHING（技术动作指导）
- 次要意图包含 TUTORIAL_REQUEST

触发后的搜索标签构建：
1. 从知识库检索命中的条目中提取标题作为搜索标签
2. 从用户消息中，通过动作别名映射表匹配已知的动作术语作为搜索标签
3. 将意图分类结果中的 action_id 实体（如有）作为精确匹配信号

推荐结果（含标题和 URL）嵌入对话响应的 `tutorialVideos` 字段中，供前端渲染。

### 4.6 视频分析报告联动触发

在视频分析流程完成后，根据诊断报告中的 `action_ids_detected` 字段：
1. 对每个检测到的动作标识调用教程推荐模块
2. 每个动作标识推荐 Top-2 教程视频
3. 将推荐结果作为 `videoLinks` 字段附加到诊断报告中

### 4.7 不可用链接提示

当推荐结果中所有教程的链接状态均为 suspect 时，系统在前端附加 `links_unverified` 警告标志，提示用户"推荐的教程链接暂未验证，如无法打开请反馈"。

## 五、本发明的关键点和欲保护点

1. **多信号源候选召回（action_id 精确匹配 + tag 语义匹配 + 标题模糊匹配）**：三种不同粒度的召回信号并行工作，兼顾精准性和覆盖面；

2. **多维度加权评分排序（相关性 + 可用性 + 质量）**：综合三个维度对候选教程进行评分排序，确保推荐结果的综合质量；

3. **链接健康感知机制**：定时自动检测教程链接可访问性，将链接状态纳入推荐排序因子，避免推荐失效链接；

4. **双通道自动触发（对话 + 视频分析）**：教程推荐不仅在用户主动请求时触发，还可在对话交流和视频分析报告生成时自动触发。

## 六、与第一条所述的最好的现有技术相比，本发明有何优点（简单介绍）？

1. **领域语义精准性**：相比通用搜索引擎的关键词匹配，本发明通过动作标识精确匹配和别名映射实现领域语义级的精准推荐。

2. **推荐质量保障**：链接健康感知和质量评分机制确保推荐给用户的教程视频既高质量又可访问。

3. **无缝集成体验**：双通道自动触发使教程推荐融入对话和视频分析的自然流程中，用户无需中断当前交互去搜索教程。

## 七、针对第四部分中的技术方案，是否还有别的替代方案同样能实现发明目的？

1. **召回方式替代**：标签语义匹配可替换为基于 Embedding 的向量相似度匹配，使用视频标题和描述的语义向量进行召回。

2. **评分权重替代**：各维度的评分权重可通过机器学习方法（如 Learning to Rank）从用户点击/观看数据中自动学习优化。

3. **链接检测替代**：除 HTTP HEAD 请求外，也可使用网页截图或视频播放性测试来验证链接的实际可播放性。

4. **触发方式替代**：除基于意图分类的规则触发外，也可使用 LLM 判断对话上下文中是否适合推荐教程（语义触发）。
