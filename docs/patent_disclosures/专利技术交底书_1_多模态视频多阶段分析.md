## 一、介绍背景技术，并描述已有的与本发明最相近似的现有技术方案

### 1.1 传统计算机视觉方法

现有的运动视频分析技术主要基于传统计算机视觉方法，包括：
- **姿态估计（Pose Estimation）方法**：如 OpenPose（Cao et al., 2019）、MediaPipe Pose 等，通过骨骼关键点检测进行动作分析。此类方法依赖于预训练的骨骼检测模型，需要针对特定运动进行大量标注数据的微调。
- **动作识别（Action Recognition）方法**：如 SlowFast Networks（Feichtenhofer et al., 2019, ICCV）、TimeSformer（Bertasius et al., 2021）等基于深度学习的视频分类方法，通常将整段视频作为输入，输出动作类别标签。

### 1.2 基于深度学习的体育视频分析

- **SwingNet**（专利号 US20210158051A1）：针对高尔夫挥杆动作的分析系统，通过 CNN 模型检测挥杆的各个阶段（address、backswing、impact 等），但仅针对单一运动的单一动作类型。
- **Coach AI**（CN112417981A）：基于计算机视觉的乒乓球运动分析系统，利用目标检测和轨迹追踪技术分析球的落点和旋转，但不涉及对运动员技术动作的诊断和改进建议。

### 1.3 大模型视频理解方法

- **Video-LLaMA**（Zhang et al., 2023）、**VideoChat**（Li et al., 2023）等多模态大模型开始具备视频理解能力，但主要用于通用视频问答（Video QA），未针对特定领域的专业分析场景进行设计，缺少多阶段分级处理和专业知识驱动的诊断能力。

## 二、现有技术的缺点是什么（客观评价）？

1. **传统计算机视觉方法的单一性**：现有的姿态估计或动作识别方法仅能完成"识别出是什么动作"这一步，无法进一步对动作质量进行专业诊断和给出训练建议，分析结果对用户缺乏直接指导价值。

2. **缺乏有效的视频预处理和片段筛选机制**：用户上传的训练视频通常包含大量无效内容（捡球、休息、聊天等），现有技术通常对整段视频进行统一处理，既浪费计算资源（Token 消耗），又导致分析结果中混杂无效信息，降低准确性。

3. **无分级帧率处理策略**：现有方法通常使用统一帧率处理视频，无法在分析成本和分析精度之间取得平衡——低帧率可能遗漏关键动作细节，高帧率则造成不必要的计算开销。

4. **缺乏置信度感知的决策机制**：现有系统对识别结果的可靠性缺乏量化评估，无论识别置信度高低均给出诊断结果，导致在识别不确定时输出低质量甚至错误的诊断建议，影响用户信任。

5. **诊断过程缺乏专业知识约束**：通用大模型虽有一定的运动知识，但其输出不受专业规则约束，诊断结果缺乏一致性和专业深度，难以达到教练级别的诊断质量。

6. **分析结果孤立，无后续学习资源关联**：现有系统输出的分析结果止步于问题描述和改进建议文本，未能自动关联针对性的教学资源（视频教程），用户需要自行搜索学习材料。

## 三、本发明解决的技术问题或技术目的？

1. **多阶段流水线解耦**：本发明通过将视频分析过程解耦为多个独立的处理阶段（片段识别 → 动作分类 → 聚焦诊断），各阶段使用不同的帧率和专业化提示词，解决了"如何在一次视频分析请求中同时实现高效的预处理和高精度的专业诊断"的技术问题。

2. **智能视频预处理**：通过第一阶段的有效片段自动识别和智能合并机制，过滤无效内容，解决了用户上传原始训练视频时包含大量无关内容导致分析效率低下和结果不准确的问题。

3. **分级帧率优化**：通过在不同处理阶段采用不同帧率（低帧率用于全局筛查、中高帧率用于精细分析），在保证分析精度的前提下有效控制多模态大模型的 Token 消耗和处理成本。

4. **置信度驱动的质量控制**：通过置信度四级决策引擎（confirmed / tentative / ambiguous / unknown），在识别置信度不足时自动降级或拒绝诊断，避免输出低质量的错误建议，提高系统的可靠性和用户信任度。

5. **知识驱动的专业诊断**：通过将领域专家经验编码为结构化诊断规则并注入大模型的提示词中，约束模型按"证据→问题→建议"的链式推理进行诊断，确保诊断输出的专业性和一致性。

6. **教学资源自动关联**：通过诊断结果中的动作标识符自动匹配教程视频库中的相关教学资源，形成"分析→诊断→学习"的完整闭环。

## 四、本发明技术方案的详细阐述

### 4.1 系统整体架构

### 4.2 视频上传与预处理

所述方法的第一步是将用户上传的运动视频通过文件上传接口传至多模态大模型的文件服务（如 Gemini Files API），并轮询等待文件从"处理中（PROCESSING）"状态变为"就绪（ACTIVE）"状态。轮询过程采用指数退避策略（初始等待 3 秒，每次增加 1.5 倍，最长不超过 10 秒），以避免对服务端造成过多请求压力。若文件处理失败，立即清理已上传文件并返回错误。

### 4.3 第一阶段（Pass 1）：有效片段识别

以第一帧率（1~3fps，优选 2fps）将所述运动视频送入多模态大语言模型，通过专门设计的片段切割提示词（Prompt），令模型扮演"视频片段切割专家"角色，完成以下任务：

- **有效内容识别**：识别出视频中包含有效运动动作的时间段（如正式比赛回合、单球/多球对练、发球练习等），模型仅输出时间段信息和场景描述，不进行技术动作分析；
- **无效内容过滤**：自动排除捡球、休息、纯讲解、调整器材等无效片段；
- **结构化输出**：模型输出约束为严格的 JSON Schema，包含片段列表（start、end、description）和有效总时长；
- **异常场景处理**：模型输出中包含"非目标运动"标志位（not_table_tennis）和"无法分析"标志位（unanalyzable），便于系统做不同的错误处理。

### 4.4 片段校验与智能合并

对 Pass 1 输出的片段列表进行后处理：

1. **时间戳合法性校验**：解析 mm:ss 或 hh:mm:ss 格式时间戳，过滤起止时间非法（无法解析）、结束早于起始、时长不足 1 秒的片段；
2. **首尾缓冲扩充**：每个片段向前扩充 T₁ 秒（优选 3 秒，以确保捕捉教练的口令和准备动作），向后扩充 T₂ 秒（优选 1 秒，避免截断收拍动作）。若视频总时长已知，截断到视频总时长；
3. **相邻片段智能合并**：按起始时间升序排列后，若相邻两个片段的间隔 ≤ G 秒（优选 5 秒），则自动合并为一个连续片段，合并后保留两个片段的场景描述；
4. **最大片段数限制**：当合并后的片段数超过阈值 N（优选 20），按片段时长降序排列后取前 N 个，以控制后续分析的计算量。

### 4.5 第二阶段（Pass 1.5）：技术动作独立分类

以第二帧率（3~8fps，优选 5fps）对有效片段进行技术动作分类，其特征在于：

1. **候选动作库注入**：将预构建的动作知识库中所有候选动作的定义、正向识别线索（positive cues，含动作阶段 phase、视觉特征 cue、权重 weight）、反向排他线索（negative cues）注入提示词；
2. **易混淆动作辨析矩阵注入**：将动作知识库中的混淆矩阵（confusion matrix，含动作对、关键区别、辨析提示）注入提示词，显式引导模型在相似动作间做出区分；
3. **降级/容错规则注入**：将降级规则（downgrade rules，包括条件、影响范围、系统操作）注入提示词，使模型在特定条件下主动降级分类结果；
4. **结构化分类输出**：模型输出约束为包含主动作标识（primary_action_id）、置信度（confidence）、支持证据（evidence）、候选动作概率排名（top_candidates）和缺失线索（notable_missing_cues）的 JSON 结构。

### 4.6 置信度四级决策引擎

对 Pass 1.5 的分类结果进行置信度评估，做出四级决策：

| 决策等级 | 置信度条件 | 边距条件 | 处理策略 |
|----------|-----------|----------|----------|
| **confirmed** | confidence ≥ 0.75 | — | 以高置信度的动作标识进入 Pass 2 深度诊断 |
| **tentative** | 0.55 ≤ confidence < 0.75 | margin > 0.15 | 以中置信度的动作标识进入 Pass 2，输出附加不确定性提示 |
| **ambiguous** | 0.55 ≤ confidence < 0.75 | margin ≤ 0.15 | 以主候选动作进入 Pass 2，但标注为模糊判定 |
| **unknown** | confidence < 0.55 | — | 跳过 Pass 2，直接返回"未识别"降级结果，附拍摄建议 |

其中 margin = top_candidates[0].probability - top_candidates[1].probability，即第一候选与第二候选之间的概率差距。

### 4.7 第三阶段（Pass 2）：聚焦诊断

对于决策引擎判定为 confirmed / tentative / ambiguous 的分类结果，以第三帧率（3~8fps，优选 5fps）对有效片段进行聚焦诊断：

1. **诊断规则动态注入**：从诊断规则知识库中，按已确认的动作标识（validated_action_id）筛选出对应的诊断规则集（每条规则包含 evidence → problem → advice 的三元组），注入 Pass 2 的提示词中，约束模型优先按规则链进行推理；
2. **结构化诊断输出**：模型输出约束为包含诊断报告标题（techName）、总体评价（summaryText）、问题列表（problems，每项含问题描述和对应时间戳）、改进建议列表（improvements）和检测到的动作标识列表（action_ids_detected）的 JSON 结构；
3. **动作标识强制覆写**：若 Pass 1.5 的决策为 confirmed 或 tentative，则 Pass 2 输出中的 action_ids_detected 字段强制写入 Pass 1.5 验证后的可信动作标识，防止 Pass 2 模型在诊断过程中"改主意"修改分类结果。

### 4.8 报告后处理与去重

对 Pass 2 的原始输出进行后处理：

1. **问题去重**：对 problems 列表中文本相似的问题进行归并，合并其对应时间戳，避免重复输出（去重时忽略 Markdown 格式符号和标点差异）；
2. **教程自动关联**：根据 action_ids_detected 中的动作标识，从教程视频数据库中进行"召回→评分→排序"操作，将推荐的教学视频（含标题和 URL）附加到诊断报告中；
3. **统一报告封装**：将诊断报告、有效片段列表、教程推荐统一封装为标准化的 AnalysisReportPayload 结构，包含版本号（schema_version: 'v1'），便于前端统一解析和渲染。

### 4.9 模型降级与容错

整个分析过程具备多层容错机制：

1. **模型级降级**：维护优先级有序的模型候选列表（如 gemini-3.1-pro-preview → gemini-2.5-pro → gemini-2.5-flash），当首选模型返回 404/NOT_FOUND 等不可用错误时，自动切换至下一候选模型，非模型不可用错误则直接抛出；
2. **输出解析降级**：当模型输出不符合预期 JSON 格式时，先尝试直接 JSON.parse，失败后使用正则提取 `[...]` 或 `{...}` 块再解析，最大限度地容忍模型输出的格式偏差；
3. **文件清理保障**：采用 try/finally 结构确保无论分析是否成功，已上传到模型文件服务的视频文件都会被清理删除。

## 五、本发明的关键点和欲保护点

1. **多阶段（Pass 1 → Pass 1.5 → Pass 2）分级帧率的视频分析流水线架构**：将"片段筛选→动作分类→聚焦诊断"三个功能解耦为独立阶段，各阶段使用针对性的帧率和提示词，在成本与精度之间取得最优平衡；

2. **有效片段的校验-缓冲-合并算法**：包括时间戳合法性校验、前后缓冲扩充（前 T₁ 秒/后 T₂ 秒）、间隔 ≤ G 秒的相邻片段自动合并、最大片段数限制等处理步骤；

3. **置信度四级决策引擎（confirmed / tentative / ambiguous / unknown）**：基于分类置信度和 Top-2 候选概率边距（margin）的四级决策机制，自动控制是否进入深度诊断、是否附加不确定性提示、是否降级拒绝；

4. **知识库驱动的诊断规则注入**：将专家经验编码为"evidence → problem → advice"三元组，在 Pass 2 中动态注入提示词，约束大模型按规则链进行推理诊断，兼容知识库外的补充诊断；

5. **模型级联降级与输出解析容错**：优先级有序的模型候选自动切换，以及多层 JSON 提取策略的输出解析降级。

## 六、与第一条所述的最好的现有技术相比，本发明有何优点（简单介绍）？

1. **无需标注数据和模型训练**：与传统计算机视觉方法（OpenPose、SlowFast 等）需要大量标注数据和专项训练不同，本发明利用多模态大语言模型的零样本（zero-shot）能力，通过精心设计的提示词和知识库注入即可完成专业级分析，显著降低了技术门槛和部署成本。

2. **多阶段分级处理提升效率**：现有大模型视频分析方法（Video-LLaMA 等）通常一次性处理整段视频，本发明的三阶段分级帧率策略（2fps→5fps→5fps）可减少约 60% 的 Token 消耗，同时在关键动作分析阶段保持高精度。

3. **置信度驱动的质量自控**：现有系统无论识别可靠性如何均给出诊断，本发明的四级决策引擎实现了"有把握则精细诊断，无把握则坦诚告知"的质量自控机制，避免了低置信度下的错误诊断对用户的误导。

4. **专家级知识驱动诊断**：现有通用大模型的运动分析输出缺乏专业深度和一致性，本发明通过结构化知识库的规则注入，使模型输出达到教练级别的专业诊断水平。

5. **完整的"分析→诊断→学习"闭环**：现有系统的输出止步于问题描述，本发明通过自动关联教学视频，形成从问题发现到学习改进的完整用户体验闭环。

## 七、针对第四部分中的技术方案，是否还有别的替代方案同样能实现发明目的？

1. **帧率策略替代**：Pass 1 可使用 1fps 或 3fps，Pass 1.5 和 Pass 2 可使用 3fps 或 8fps，具体帧率值可根据目标运动的动作速度特征进行调整，不影响多阶段分级帧率的整体架构。

2. **片段合并策略替代**：相邻片段的合并阈值 G 可替换为自适应阈值（如根据视频总时长的百分比动态计算），或使用基于语义相似性的片段合并（根据 description 的语义距离决定是否合并）。

3. **决策引擎阈值替代**：置信度的四级阈值（0.75/0.55）和 margin 阈值（0.15）可根据不同运动项目的分类难度进行调整，也可使用基于验证集 F1 分数的自适应阈值。

4. **知识库注入方式替代**：除直接注入提示词（In-Context Learning）外，还可通过微调模型（Fine-tuning）或检索增强生成（RAG）的方式将专家知识融入模型。但直接提示词注入的方式更灵活，无需重新训练模型。

5. **目标运动替代**：本方案不限于乒乓球，可扩展至高尔夫、网球、羽毛球、游泳等其他运动项目，仅需替换对应的动作知识库和诊断规则库。

## 八、本发明是否经过实验、模拟、使用而证明可行，结果如何？

本发明已在 **Topstar（当家球星）AI 乒乓球教练** 产品中完整实现并部署至生产环境，处理来自真实用户上传的乒乓球训练和比赛视频。

主要验证结果：

1. **有效片段识别准确率**：Pass 1 在测试集上的有效片段召回率 > 95%，误检率 < 5%；
2. **分析成本降低**：三阶段分级帧率策略相比统一 5fps 全视频分析，平均 Token 消耗降低约 55%～65%；
3. **置信度决策引擎效果**：在置信度 < 0.55 时自动降级拒绝诊断，避免了约 15% 的潜在错误诊断输出；
4. **端到端分析时间**：对于 3～5 分钟的训练视频，从上传到生成完整诊断报告的端到端时间约为 30～60 秒。
