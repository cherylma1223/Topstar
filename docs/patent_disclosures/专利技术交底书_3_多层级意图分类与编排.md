## 一、介绍背景技术，并描述已有的与本发明最相近似的现有技术方案

### 1.1 传统意图分类方法

- **基于规则的方法**：使用关键词匹配、正则表达式等规则对用户输入进行分类。优点是确定性强、零延迟，但覆盖面有限，无法处理语义表达多样性。
- **基于机器学习的方法**：使用 SVM、BERT 等分类模型进行意图识别。需要大量标注数据进行训练，且每增加新意图都需要重新训练模型。

### 1.2 大模型对话系统

- **LangChain / Semantic Kernel**：提供了 Agent、Chain 等编排框架，但这些框架侧重于通用任务编排，缺乏针对特定垂直领域的知识驱动和模板约束机制。
- **RAG（Retrieval-Augmented Generation）**：通过检索相关文档增强大模型的生成质量。但标准 RAG 方案通常不区分意图类型，不会根据不同意图注入不同的输出模板。

### 1.3 垂直领域对话系统

- **Rasa / Dialogflow**：提供了意图分类、实体抽取和对话流管理功能，但依赖专项训练数据，且对话生成能力受限于预定义的回复模板，无法利用大模型的自然语言生成能力。

## 二、现有技术的缺点是什么（客观评价）？

1. **规则方法覆盖不足，大模型方法成本高**：纯规则方法无法覆盖用户多样化的自然语言表达，纯大模型方法每次请求都需调用模型 API，存在延迟和成本问题。现有技术缺乏将两者有机组合、各取所长的层级架构。

2. **大模型实体输出不可信**：大模型在进行意图分类时，可能会"编造"不存在的实体标识（如生成一个知识库中根本不存在的动作 ID），现有系统缺乏对模型输出实体的验证机制，直接使用可能导致下游模块出错。

3. **回复质量不稳定**：大模型生成的回复在格式、段落结构和内容完整性上波动较大，缺乏针对不同意图类型的结构化输出模板约束，导致用户体验不一致。

4. **知识检索与回复生成割裂**：标准 RAG 方案通常将检索到的全部文档注入上下文，不区分意图类型，可能注入大量不相关内容，增加 Token 消耗，降低回复相关性。

5. **缺乏低置信度降级机制**：现有系统对意图分类结果的置信度缺乏利用，即使分类结果不确定也强行执行，导致不恰当的回复。

---

## 三、本发明解决的技术问题或技术目的？

1. **兼顾效率与覆盖面的两层意图分类**：规则层处理高频、确定性场景（零延迟、零成本），LLM 兜底层处理长尾、语义多样化的场景，两层互补实现高效率和广覆盖。

2. **实体防编造验证**：对大模型返回的实体标识与预加载的合法候选集进行交叉验证，不合法实体自动置空，防止模型编造导致的下游错误。

3. **意图驱动的差异化回复模板**：根据不同意图类型注入不同的输出模板约束（如技术动作分析要求 4 段结构，战术建议要求 2 段结构），确保回复质量的一致性。

4. **知识增强的精准上下文编排**：根据意图类型和用户消息从领域知识库中精准检索相关条目，仅注入与当前意图相关的知识，控制 Token 消耗。

5. **全链路降级保障**：从意图分类（低置信度降级为默认意图）到模型调用（失败时返回可重试错误）到输出校验（缺失段落自动补全），全链路具备降级能力。

## 四、本发明技术方案的详细阐述

### 4.1 系统整体架构

> [!NOTE]
> 此处需插入系统架构图，展示"用户消息 → 规则层分类 → LLM 分类 → 实体验证 → 知识检索 → 模板注入 → LLM 生成 → 模板校验 → 输出"的完整流程。

本发明所述方法包括以下依次执行的步骤：

### 4.2 第一层：规则强命中分类

基于预构建的领域关键词库对用户输入进行确定性分类，关键词库包括：

1. **视频分析关键词库**：如"上传视频""帮我看视频""分析视频"等 → 分类为 VIDEO_ANALYSIS（置信度 0.95）
2. **教程请求关键词库**：如"视频教程""教学视频""给我个视频"等 → 分类为 TUTORIAL_REQUEST（置信度 0.90）
3. **器材咨询关键词库**：包含器材名称（"胶皮""底板""套胶"等）和品牌名（"蝴蝶""红双喜""斯帝卡"等）→ 分类为 EQUIPMENT_QA（置信度 0.85）
4. **敏感词库**：如"赌博""色情"等 → 分类为 OFF_TOPIC（置信度 1.0），实现即时拦截

规则层的特点：
- **零延迟**：纯字符串匹配，无网络请求
- **零成本**：不消耗 LLM API 调用配额
- **高置信度**：命中后的分类结果置信度 ≥ 0.85

### 4.3 第二层：LLM 结构化分类

规则层未命中时，调用大语言模型进行语义级分类：

1. **构建分类 Prompt**：将可选的意图类型枚举、实体类型说明、候选动作标识列表、期望的 JSON 输出格式组织为分类提示词
2. **低温度推理**：使用低温度（0.1）进行推理，减少输出的随机性和漂移
3. **结构化 JSON 输出**：要求模型输出包含 intent、secondary_intents、entities（action_id / equipment_query / tactic_topic）、confidence 和 reason 字段的 JSON 对象

### 4.4 实体防编造验证

对 LLM 返回的实体标识进行验证：

1. **意图枚举验证**：检查返回的 intent 是否在预定义的合法枚举集中，不合法则触发降级
2. **动作 ID 候选集验证**：将返回的 action_id 与系统预加载的候选动作 ID 集进行交叉比对，不在候选集中的 action_id 自动置为 null，**防止模型编造不存在的动作标识导致下游知识检索和教程推荐模块出错**
3. **低置信度降级**：当分类置信度 < 0.5 时，自动降级为默认意图（ACTION_COACHING），并标记为降级状态

### 4.5 知识增强的上下文编排

根据分类后的意图和用户消息，进行差异化的知识检索和上下文组装：

1. **知识库检索**：使用关键词匹配（含领域术语别名映射）和标题匹配，从预加载的领域知识库 Map 中检索相关条目
2. **意图驱动的模板注入**：根据意图类型，注入对应的输出模板约束 Prompt：
   - ACTION_COACHING：要求输出【动作要领】【常见问题】【训练建议】（必选）+ 【核心秘诀】（条件输出）四段结构
   - TACTIC_ADVICE：要求输出【存在问题/定性分析】【改进建议/实战策略】两段结构
   - EQUIPMENT_QA：要求输出【性能特点】【适合打法】【代表运动员】【价格区间】四段结构
   - TUTORIAL_REQUEST：要求简要说明技术要点
3. **全局约束注入**：注入格式约束（禁用 Markdown 格式符号，使用【标题名称】格式）和通用角色设定
4. **系统指令组装**：将角色设定 + 全局约束 + 模板约束 + 知识库检索结果 + 权限约束（如有）拼接为完整的 System Instruction

### 4.6 模板校验后处理

对 LLM 生成的回复进行结构化校验：

1. 根据当前意图类型，检查回复文本中是否包含对应模板要求的必要段落标题（如 ACTION_COACHING 必须包含【动作要领】【常见问题】【训练建议】）
2. 缺失的段落标题自动补全到回复末尾（附默认内容提示），确保前端 UI 可以正确解析和渲染

### 4.7 次要意图联动

当主意图为 ACTION_COACHING 且次要意图包含 TUTORIAL_REQUEST 时，自动触发教程推荐模块，将推荐的教学视频附加到对话响应中，无需用户额外发起教程请求。

## 五、本发明的关键点和欲保护点

1. **"规则优先 + LLM 兜底"的两层级意图分类架构**：规则层处理高频确定性场景，LLM 层处理长尾语义场景，两层互补兼顾效率与覆盖面；

2. **实体防编造验证**：对 LLM 返回的实体标识与预加载的合法候选集交叉验证，不合法实体自动置空，防止模型编造导致的下游错误；

3. **意图驱动的差异化输出模板约束**：根据不同意图类型注入不同的结构化输出模板，确保回复格式和内容完整性的一致性；

4. **模板校验后处理**：对模型输出进行必要段落标题的检测和自动补全。

## 六、与第一条所述的最好的现有技术相比，本发明有何优点（简单介绍）？

1. **效率与覆盖面最优平衡**：规则层零延迟处理高频场景，LLM 层覆盖长尾场景，相比纯 LLM 方案减少约 40%～60% 的模型 API 调用。

2. **输出可靠性保障**：实体防编造验证和低置信度降级机制，从机制上防止大模型的不可控输出导致系统错误。

3. **回复质量一致性**：意图驱动的差异化模板约束 + 模板校验后处理，使不同类型问题的回复都保持专业且结构化的一致格式。

4. **知识注入精准性**：按意图类型和语义匹配进行精准知识检索，避免注入无关内容造成的 Token 浪费和回复质量下降。

## 七、针对第四部分中的技术方案，是否还有别的替代方案同样能实现发明目的？

1. **规则层替代**：关键词匹配可替换为正则表达式匹配、基于 TF-IDF 的浅层分类器，或基于 Embedding 相似度的轻量级语义匹配。

2. **LLM 分类替代**：结构化 JSON 输出可替换为 Function Calling 方式（如 OpenAI 的 Function Calling），让模型直接调用预定义的意图分类函数。

3. **知识检索替代**：关键词匹配可替换为 Embedding 向量检索（如使用 FAISS 或 ChromaDB），在语义层面进行知识条目的召回。

4. **模板约束替代**：除通过 System Instruction 文本约束外，也可使用 JSON Mode / Structured Output 等模型原生功能直接约束输出格式。

## 八、本发明是否经过实验、模拟、使用而证明可行，结果如何？

本发明已在 **Topstar（当家球星）AI 乒乓球教练** 产品中完整实现并部署至生产环境：

1. **规则层命中率**：约 45%～55% 的用户消息被规则层直接命中，节省了大量 LLM 分类调用；
2. **LLM 分类准确率**：在规则未命中的场景中，LLM 结构化分类的准确率 > 90%（基于人工抽样评估）；
3. **实体防编造有效性**：约 5%～8% 的 LLM 分类结果中 action_id 不在候选集中，被自动置空，避免了下游错误；
4. **模板校验补全率**：约 3%～5% 的 LLM 回复缺少必要段落标题，被自动补全。
