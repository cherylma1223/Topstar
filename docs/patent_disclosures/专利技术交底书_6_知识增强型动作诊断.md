### 术语解释

| 术语 | 解释 |
|------|------|
| 识别知识库（Recognition Knowledge Base） | 存储每个技术动作的识别线索的结构化知识库，包含正向线索、反向线索和易混淆矩阵，用于辅助模型进行动作分类 |
| 诊断知识库（Diagnosis Knowledge Base） | 存储每个技术动作的诊断规则的结构化知识库，每条规则包含"视觉证据→问题诊断→训练建议"的三元组 |
| 正向识别线索（Positive Cues） | 如果在视频中观察到则增加该动作分类置信度的视觉特征，每条线索包含动作阶段（phase）、视觉特征描述（cue）和权重（weight） |
| 反向排他线索（Negative Cues） | 如果在视频中观察到则降低该动作分类置信度的视觉特征，用于排除不相关的动作 |
| 易混淆动作辨析矩阵（Confusion Matrix） | 记录两两之间容易混淆的动作对，及其关键区别和辨析方法 |
| 降级规则（Downgrade Rules） | 在特定条件下（如视频质量差、角度不佳等）降低分类或诊断结果确信度的规则 |
| 链式推理 | 模型按照"若看到证据 X → 诊断为问题 Y → 建议 Z"的因果链进行推理的方式 |

## 一、介绍背景技术，并描述已有的与本发明最相近似的现有技术方案

### 1.1 基于知识图谱的运动分析

- **运动知识图谱**：学术界有构建运动领域知识图谱的研究（如 SportKG），但这些知识图谱主要存储运动员、赛事、成绩等实体关系，不涉及技术动作的视觉识别线索和诊断规则。

### 1.2 基于专家规则的运动诊断

- **传统专家系统**：早期的运动技术诊断系统采用 if-then 规则引擎，将教练的诊断经验编码为固定规则。但这类系统需要精确的结构化输入（如骨骼关键点坐标），无法直接处理原始视频，且规则维护成本高。

### 1.3 基于大模型的通用视频分析

- **多模态大模型**（如 GPT-4V、Gemini）具备直接理解视频内容的能力，可以对视频中的动作进行描述和评价。但通用模型缺乏对特定运动项目的深度专业知识，其输出的诊断建议：
  - 缺乏一致性：对同一动作问题的描述在不同请求中可能完全不同
  - 缺乏专业深度：可能遗漏专业教练关注的关键问题
  - 可能出现"幻觉"：编造不存在的技术问题或给出不正确的建议

## 二、现有技术的缺点是什么（客观评价）？

1. **通用大模型缺乏领域专业深度**：虽然多模态大模型具备视频理解能力，但其预训练知识中关于特定运动项目的专业诊断知识有限，输出的诊断建议往往停留在泛泛的描述层面（如"动作不够流畅""注意发力"），缺乏教练级别的具体和深度（如"引拍时肘部外展角度过大，导致触球瞬间摩擦向量偏离"）。

2. **诊断输出不一致**：通用大模型对同一视频中的同一技术问题，在不同请求中可能给出完全不同的诊断描述和建议，缺乏可重复性，不利于用户持续跟踪训练进度。

3. **缺乏结构化的动作识别约束**：通用模型在分类动作时缺乏对特定运动项目动作体系的结构化理解，不知道哪些动作容易混淆、各动作的关键视觉区别是什么，导致分类容易出错。

4. **专家经验难以系统化利用**：教练的诊断经验通常以口头传授或文字教案的形式存在，难以被直接注入大模型中系统化利用。传统的知识工程方法需要构建复杂的知识图谱或专家系统，开发成本高。

5. **知识库更新与系统可用性的耦合**：当结构化知识库不可用或需要更新时（如新增动作类型），系统通常需要停机更新或重新训练模型，缺乏降级容错机制。

## 三、本发明解决的技术问题或技术目的？

1. **将专家经验系统化编码**：本发明提出了一种将领域专家（教练）的识别经验和诊断经验分别编码为两个结构化知识库的方法，使专家知识可以被大模型直接利用。

2. **知识驱动的精准识别**：通过将正向识别线索、反向排他线索和易混淆矩阵注入模型提示词，引导模型按专家的识别逻辑进行分类，提升分类准确性和可解释性。

3. **知识驱动的专业诊断**：通过将"evidence → problem → advice"三元组规则注入模型提示词，约束模型按专家的诊断逻辑进行链式推理，确保诊断输出的专业深度和一致性。

4. **双库协同的完整链路**：识别知识库和诊断知识库通过动作标识（action_id）关联，形成"精准识别→专业诊断"的完整链路。

5. **降级容错保障**：当结构化 JSON 知识库不可用时，自动从非结构化的 Markdown 知识文件中解析提取识别线索和诊断规则，保证系统可用性。

## 四、本发明技术方案的详细阐述

### 4.1 双知识库架构

本发明构建两个独立但关联的结构化知识库：

> [!NOTE]
> 此处需插入双知识库架构图，展示识别知识库和诊断知识库的结构及其通过 action_id 的关联关系。

#### 4.1.1 识别知识库（Recognition Knowledge Base）

以 JSON 格式存储，包含以下数据结构：

**动作定义集合**：每个技术动作包含：
- `id`：动作唯一标识（如 `fh_loop`、`bh_push`）
- `title`：动作中文名称
- `aliases`：别名列表（如 `["反手拧拉", "反手台内拧", "ChiQuita"]`）
- `definition`：一句话定义
- `scope`：适用范围（含排他场景列表）
- `positive_cues`：正向识别线索列表，每条含：
  - `phase`：动作阶段（如"引拍""触球""随挥"）
  - `cue`：视觉特征描述（如"持拍手的手腕明显内收，拍面近乎垂直或稍前倾"）
  - `weight`：该线索的权重（1-5），权重越高表示该线索对分类的鉴别力越强
  - `why`（可选）：解释为何该线索能区分此动作与其他动作
  - `missing_policy`（可选）：当该线索缺失时的处理策略
- `negative_cues`：反向排他线索列表，每条含：
  - `phase`：动作阶段
  - `cue`：若观察到则应排除此动作的视觉特征

**易混淆动作辨析矩阵**：每条记录包含：
- `action_id` / `confusable_with`：容易混淆的两个动作
- `key_difference`：关键区别描述
- `secondary_difference`（可选）：次要区别
- `required_visible_info`：做出正确区分所需的最低可见信息列表
- `low_confidence_policy`（可选）：在低置信度时的处理策略
- `prompt_snippet`（可选）：注入模型提示词的辨析提示片段

**降级规则集合**：每条规则包含：
- `scope`：规则作用范围（`global` 全局 / `action` 特定动作）
- `action_id`（可选）：针对的动作标识
- `rule_type`：规则类型
- `condition`：触发条件描述
- `affects`：影响的对象
- `system_action`：系统应执行的操作
- `user_message`（可选）：用户提示信息

#### 4.1.2 诊断知识库（Diagnosis Knowledge Base）

以 JSON 格式存储，包含诊断规则列表，每条规则包含：
- `action_id`：关联的动作标识
- `issue_id`：问题唯一标识
- `evidence`：视觉证据描述（如"击球时手臂过于僵硬，缺少自然的鞭打动作"）
- `problem`：问题诊断描述（如"肘部发力不充分，影响击球质量和旋转"）
- `priority`：诊断优先级（1-5），数值越高越应优先关注
- `advice`：训练建议（如"练习单纯的前臂挥拍，不击球，感受鞭打发力的节奏"）
- `related_cues`：与此诊断规则相关的识别线索 ID 列表

### 4.2 识别知识库在分类中的应用

在视频分析的动作分类阶段（Pass 1.5），将识别知识库的内容注入模型提示词：

1. **候选动作库注入**：将所有动作的 id、title、definition 和正向/反向线索列表组织为自然语言描述，注入提示词中，使模型了解完整的动作候选空间
2. **易混淆矩阵注入**：将混淆矩阵中的辨析方法以自然语言形式注入，显式引导模型在关键区分点上做出正确判断
3. **降级规则注入**：将降级规则以条件-动作的形式注入，使模型在特定条件下主动降低置信度或拒绝分类

模型在分类时被约束为：
- 匹配正向线索时增加对应动作的置信度
- 发现反向线索时降低对应动作的置信度
- 在易混淆动作之间，根据辨析矩阵中的关键区别做出判断

### 4.3 诊断知识库在诊断中的应用

在视频分析的聚焦诊断阶段（Pass 2），将诊断知识库中对应动作的规则注入模型提示词：

1. **规则筛选**：根据 Pass 1.5 确认的动作标识（validated_action_id），从诊断规则库中筛选出该动作的所有诊断规则
2. **链式推理注入**：将规则以"若看到证据 X → 诊断为问题 Y → 建议 Z"的格式注入提示词

示例注入格式：
```
【诊断规则约束】
系统已认定该动作为【fh_loop】。请严格对照以下规则进行诊断：
- 如果看到视觉证据: "引拍幅度过大，超过身体后方" -> 诊断为: "引拍过大导致击球时间延迟" -> 训练建议: "限制引拍角度在45度以内"
- 如果看到视觉证据: "击球时手臂完全伸直" -> 诊断为: "缺少前臂加速，影响旋转质量" -> 训练建议: "练习收前臂的鞭打发力"
如果遇到规则以外的问题，可以补充，但必须优先匹配上述规则。
```

3. **兼容规则外补充**：在优先匹配规则库中的已知问题的前提下，允许模型补充规则库中未覆盖的新发现问题。

### 4.4 双库协同机制

两个知识库通过 action_id 关联，形成完整的"识别→诊断"链路：

```
识别知识库 (action_id: fh_loop)
  ├── positive_cues → 引导 Pass 1.5 识别出 fh_loop
  ├── negative_cues → 排除不是 fh_loop 的情况  
  └── confusion_matrix → 区分 fh_loop vs bh_loop

       ↓ validated_action_id = fh_loop

诊断知识库 (action_id: fh_loop)
  ├── rule_1: evidence → problem → advice
  ├── rule_2: evidence → problem → advice
  └── rule_n: evidence → problem → advice
       ↓ 注入 Pass 2 → 链式推理诊断
```

### 4.5 Markdown 降级解析

当结构化 JSON 知识库文件不可用时（如文件丢失、格式错误），系统自动从 Markdown 格式的知识文件中解析提取信息：

1. **正向线索提取**：从 Markdown 中的 `### 【动作要领】` 段落解析技术要点，转化为简化版 positive_cues
2. **诊断规则提取**：从 Markdown 中的 `### 【常见问题与纠错建议库】` 段落解析问题-建议对，转化为简化版诊断规则
3. **降级标记**：解析产生的知识库 schema_version 标记为 `'fallback'`，提示系统当前运行在降级模式

降级模式下，知识库不包含 negative_cues、confusion_matrix 和 downgrade_rules，分类精度会有所下降，但系统仍可正常运行。

## 五、本发明的关键点和欲保护点

1. **双知识库架构（识别知识库 + 诊断知识库）**：将专家的识别经验和诊断经验分别编码为两个独立的结构化知识库，各自服务于不同的分析阶段，通过 action_id 关联形成完整链路；

2. **正向/反向识别线索体系**：每个动作包含带权重的正向线索（观察到则加分）和反向线索（观察到则减分），实现基于专家经验的结构化识别约束；

3. **易混淆动作辨析矩阵**：显式定义两两容易混淆的动作对及其关键区别和辨析方法，引导模型在关键区分点上做出正确判断；

4. **"evidence → problem → advice" 三元组链式推理规则**：将专家的诊断逻辑编码为结构化的因果链规则，注入模型提示词后驱动模型进行链式推理诊断；

5. **Markdown 降级解析容错**：当 JSON 知识库不可用时，自动从 Markdown 知识文件中解析提取信息，保证系统可用性。

## 六、与第一条所述的最好的现有技术相比，本发明有何优点（简单介绍）？

1. **专家知识系统化利用**：与通用大模型直接分析视频相比，本发明通过结构化知识库将教练级专家经验系统化注入模型，使输出达到教练级的专业深度和一致性。

2. **无需模型训练**：与传统专家系统或知识图谱方案需要复杂的知识工程或模型训练不同，本发明通过提示词注入（In-Context Learning）的方式利用知识库，知识更新只需修改 JSON 文件，无需重新训练模型。

3. **可解释的诊断逻辑**：三元组规则的链式推理方式使每个诊断结论都可追溯到具体的视觉证据和规则依据，提升了诊断结果的可解释性和可信度。

4. **高度可扩展**：知识库的结构化设计使其可方便地扩展到新的运动项目，只需编写新项目的识别和诊断知识库文件即可，无需修改系统代码。

5. **降级容错**：Markdown 降级解析确保系统在知识库文件异常时仍可提供基本服务，而非完全不可用。

## 七、针对第四部分中的技术方案，是否还有别的替代方案同样能实现发明目的？

1. **知识库格式替代**：JSON 格式可替换为 YAML、TOML 或数据库存储，不影响整体架构。

2. **知识注入方式替代**：
   - **微调（Fine-tuning）**：将知识库内容用于模型微调，使知识内化到模型参数中。优点是推理时不占上下文长度，缺点是知识更新需要重新微调。
   - **RAG（检索增强生成）**：通过向量数据库存储知识库，每次请求时检索最相关的知识条目注入。优点是知识库规模不受上下文窗口限制，缺点是检索精度影响诊断质量。

3. **线索权重替代**：固定权重可替换为基于用户反馈或专家评估动态调整的自适应权重。

4. **混淆矩阵构建方式替代**：除专家手动定义外，也可通过分析模型的历史分类错误自动发现容易混淆的动作对。

5. **运动项目替代**：本方案可扩展至高尔夫（挥杆分析）、网球（发球/底线分析）、羽毛球（步法/手法分析）、游泳（泳姿分析）等其他运动项目。

## 八、本发明是否经过实验、模拟、使用而证明可行，结果如何？

本发明已在 **Topstar（当家球星）AI 乒乓球教练** 产品中完整实现并部署至生产环境：

1. **识别知识库规模**：已覆盖乒乓球主要技术动作（正手攻球、反手拨球、正手拉球、反手拉球、搓球、发球等），每个动作包含 5-15 条正向线索和 2-5 条反向线索；
2. **诊断知识库规模**：已编写超过 50 条诊断规则，覆盖主要动作的常见技术问题；
3. **知识注入效果**：使用知识库注入后，模型的动作分类准确率提升约 15%～25%，诊断输出的专业深度和一致性显著改善；
4. **降级容错验证**：在移除 JSON 知识库文件后，系统成功切换至 Markdown 降级模式，仍可提供基本的分析服务。
