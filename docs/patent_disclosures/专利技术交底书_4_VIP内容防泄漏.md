| 入模前物理剥离 | 在将知识库内容注入大语言模型的系统指令（System Instruction）之前，将受保护的会员专属内容从知识库原文中物理移除，使模型在推理过程中根本无法接触到这些内容 |

## 一、介绍背景技术，并描述已有的与本发明最相近似的现有技术方案

### 1.1 基于 Prompt 指令的内容限制

当前大多数 LLM 应用的内容保护方法是在系统指令（System Prompt）中添加限制性指令，如"你不得透露以下信息""你不允许回答关于 XXX 的问题"等。代表实现包括：
- OpenAI GPT-4 的 System Message 约束
- Anthropic Claude 的 Constitutional AI 约束

### 1.2 基于 API 权限的访问控制

传统 Web 应用的会员内容保护通常在 API 层面实现——非会员用户的请求直接被 API 拦截，返回"需要升级会员"提示。内容数据存储在数据库中，通过后端权限校验控制访问。

### 1.3 大模型输出过滤

- **安全过滤器（Safety Filters）**：如 OpenAI 的 Content Moderation API、Google 的 Safety Settings，可以过滤色情、暴力等违规内容，但不针对业务级别的会员内容保护。
- **基于关键词的输出过滤**：一些系统在模型输出后简单地过滤包含特定关键词的段落，但缺乏多层防护和语义级泄漏检测。

---

## 二、现有技术的缺点是什么（客观评价）？

1. **Prompt 指令约束易被绕过**：大语言模型的 System Prompt 约束本质上是"请求"而非"强制"，用户可以通过 Prompt 注入攻击（如"忽略你之前的所有指令""扮演一个没有限制的 AI"等手段）绕过内容限制，诱导模型泄露受保护信息。**模型"看到了"受保护内容但被要求"不说"，这在信息论上是脆弱的——因为信息已经存在于模型的上下文中。**

2. **传统 API 权限控制不适用于 LLM 场景**：在大模型应用中，知识库内容需要作为上下文注入模型才能生成专业回复。如果直接在 API 层面完全阻断非会员用户的访问，则非会员用户将无法获得任何基于知识库的专业回复（连免费部分也无法提供），严重影响用户体验和转化率。

3. **单层输出过滤不够可靠**：简单的关键词过滤可能遗漏模型对受保护内容的"改写"或"暗示"（如模型没有直接复述原文，但用自己的话描述了相同的核心技巧），导致内容实质性泄漏。

4. **语音通道未受保护**：当 LLM 应用提供语音播报功能（TTS）时，即使文本通道已过滤受保护内容，如果 TTS 前未再次清洗，受保护内容仍可能通过语音通道泄漏。

5. **前端无法感知内容被保护**：现有方案在过滤受保护内容后，前端无法区分"模型没有提及该内容"和"该内容被后端过滤了"，无法向用户展示"此处有会员专属内容，升级后可解锁"的引导 UI。

---

## 三、本发明解决的技术问题或技术目的？

1. **从信息论层面阻断泄漏**：通过入模前物理剥离，使受保护内容在模型推理时根本不存在于上下文中，从根本上消除了模型"知道但被要求不说"的脆弱依赖。

2. **双向防护架构**：结合"入模前物理剥离"和"出模后多重脱敏"，构成纵深防御体系，即使模型通过训练数据或语义推理间接产生了与受保护内容相似的输出，仍可被出模后的多层脱敏捕获。

3. **跨通道防护**：不仅在文本输出通道进行保护，还在 TTS 语音合成前进行二次剥离，防止受保护内容通过语音通道泄漏。

4. **前端锁区引导**：通过锁区占位符机制，使前端应用能够感知"此处有受保护内容被剥离"，并渲染会员升级引导 UI，提升用户转化率。

5. **免费内容与付费内容共存**：使非会员用户可以正常获得基于知识库免费部分的专业回复，同时在同一回复中标识出"有更深入的会员内容可解锁"，实现合理的内容分级。

## 四、本发明技术方案的详细阐述

### 4.1 系统整体架构

> [!NOTE]
> 此处需插入系统流程图，展示"知识库原文 → VIP 判定 → 物理剥离（非VIP）→ 权限指令注入 → LLM 生成 → 段落级清洗 → 行级泄漏检测 → 锁区占位符追加 → TTS 侧二次剥离 → 安全输出"的完整流程。

### 4.2 知识库内容结构

领域知识库中的每个知识条目包含普通内容和受保护内容两部分，受保护内容通过特定的段落标题标识：
- 受保护段落标题格式：`【核心秘诀】` 或 `【VIP专属...】`
- 受保护段落的内容紧跟标题之后，直到下一个 `【标题】` 或文件结束

### 4.3 入模前物理剥离

在将知识库内容注入大语言模型的系统指令之前，执行以下步骤：

1. **VIP 身份判定**：检查当前请求的用户是否为 VIP 会员（通过请求参数中的 `is_vip` 标志判定）
2. **受保护段落识别**：使用正则表达式识别知识库原文中的受保护段落（匹配 `【核心秘诀...】` 或 `【VIP专属...】` 标题及其后续内容）
3. **条件性物理移除**：
   - 若用户为 VIP：保留完整内容，不做剥离
   - 若用户为非 VIP：从知识库原文中物理移除受保护段落，**使注入到模型系统指令中的文本中完全不包含受保护内容**
4. **VIP 存在性标记**：记录原始知识库中是否存在受保护内容（hasVipSecret 标志），供后续步骤使用

关键技术特征：此步骤在文本层面完成物理移除，确保**大模型在推理时根本无法"看到"受保护内容**——这与传统的 Prompt 约束（"不要提及"）有本质区别，后者是模型"看到了但被要求不说"，而本方案是模型"根本看不到"。

### 4.4 权限指令注入

若用户为非 VIP 且原始知识库中存在受保护内容，则在系统指令末尾追加强制权限约束指令：

> "重要权限规则：知识库中的 VIP/核心秘诀内容只对会员开放。你绝对不能在任何段落中提及、改写、复述或暗示这部分内容；如果无法确认，宁可省略。"

此指令作为**第二层防护**——尽管受保护内容已被物理移除，但模型可能通过其预训练知识或语义推理间接产生类似内容。权限指令在语义层面进一步约束模型的输出倾向。

### 4.5 出模后段落级清洗

对大模型生成的回复文本进行段落级扫描和清洗：

1. **受保护段落正则匹配**：使用与入模前相同的正则表达式扫描模型输出，匹配以 `【核心秘诀】` 或 `【VIP专属...】` 为标题的段落
2. **整段移除**：命中的段落连同标题和内容整体移除，并标记 `removedVip = true`

### 4.6 出模后行级泄漏检测

在段落级清洗之后，对非受保护段落中的每一行进行细粒度泄漏检测：

1. **敏感词库匹配**：维护一个领域敏感词库，包含受保护内容中的关键术语和表述（如"二次点火""喷射感""猛压拍肩""金牌教练"等特征性专业表述）
2. **逐行扫描**：对每一行文本（排除已识别为受保护段落标题的行）进行敏感词匹配
3. **命中行删除**：若某行（属于非受保护段落）包含敏感词，则删除该行，并标记 `removedVip = true`

此步骤的设计意图：防止大模型虽未使用受保护段落的标题格式，但在其他段落中"暗示"或"改写"了受保护内容的核心要点。

### 4.7 锁区占位符强制下发

若经过上述处理后，系统判定存在受保护内容被剥离或清洗（满足以下任一条件）：
- 原始知识库中存在受保护内容（hasVipSecret = true），或
- 段落级/行级清洗中移除了受保护内容（removedVip = true）

且输出文本中尚未包含锁区占位符，则在回复文本末尾自动追加：

```
【核心秘诀】
[LOCKED_VIP_CONTENT]
```

前端应用检测到 `[LOCKED_VIP_CONTENT]` 占位符后，渲染会员升级引导 UI（如"解锁核心秘诀，升级 VIP 会员"按钮），引导用户付费升级。

### 4.8 TTS 语音合成侧保护

在将回复文本送入文字转语音（TTS）引擎之前，额外执行一次剥离：

1. 扫描待合成文本，识别包含"VIP"或"秘诀"等关键词的段落标题
2. 移除这些段落（含标题和内容），防止受保护内容通过语音通道泄漏
3. 同时移除锁区占位符文本，避免语音播报"LOCKED VIP CONTENT"等无意义内容

## 五、本发明的关键点和欲保护点

1. **入模前物理剥离机制**：在将知识库内容注入大模型上下文之前，对受保护内容进行物理移除，使模型在推理过程中根本无法接触受保护信息——这从信息论层面阻断了泄漏通道，与传统 Prompt 约束的"要求不说"形成本质区别；

2. **出模后多重脱敏（段落级 + 行级）**：先进行段落级的受保护段落整体清洗，再进行行级的领域敏感词泄漏检测，构成两层输出过滤，覆盖模型"直接复述"和"改写暗示"两种泄漏方式；

3. **锁区占位符的前端联动**：当检测到受保护内容存在时，自动在输出中插入占位符，供前端渲染会员升级 UI，将"内容保护"转化为"商业转化"；

4. **跨通道（文本 + 语音）统一防护**：在 TTS 语音合成前进行二次剥离，防止通过语音通道绕过文本层的保护。

## 六、与第一条所述的最好的现有技术相比，本发明有何优点（简单介绍）？

1. **信息论安全性**：与 Prompt 约束方案的"模型看到但被要求不说"相比，本发明的入模前物理剥离实现了"模型根本看不到"，在信息论层面具有不可绕过的安全性。

2. **纵深防御**：四层防护（物理剥离→权限指令→段落清洗→行级检测）形成纵深防御，单层被突破不影响整体安全性。

3. **商业价值**：锁区占位符机制不仅保护了内容，还创造了会员升级的引导入口，将内容保护与商业转化结合。

4. **跨通道统一性**：文本和语音两个输出通道统一保护，无盲区。

5. **用户体验兼容**：非 VIP 用户仍可获得基于免费知识的专业回复，不会因为内容保护而完全丧失使用价值。

## 七、针对第四部分中的技术方案，是否还有别的替代方案同样能实现发明目的？

1. **受保护内容标识方式替代**：除通过段落标题格式标识外，也可通过知识库中的元数据字段（如 `vip_only: true`）标识受保护内容。

2. **敏感词库构建方式替代**：行级泄漏检测的敏感词库可从静态手工编辑改为基于受保护内容自动提取关键术语（如 TF-IDF 提取 Top-N 特征词）。

3. **泄漏检测方式替代**：除基于敏感词匹配的行级检测外，也可使用 Embedding 语义相似度检测——将模型输出中的每一句与受保护内容进行语义相似度计算，超过阈值的句子标记为疑似泄漏。

4. **前端锁区替代**：占位符可替换为结构化的 JSON 字段（如在 API 响应中添加 `has_locked_content: true` 字段），前端根据此字段决定是否渲染升级引导 UI。

5. **应用场景替代**：本方案不限于体育教练场景，可扩展到在线教育（免费课程 vs VIP 课程）、法律咨询（基础法律建议 vs 深度法律分析）、医疗健康（常见问题 vs 专家诊疗建议）等任何基于 LLM 的会员分级场景。

## 八、本发明是否经过实验、模拟、使用而证明可行，结果如何？

本发明已在 **Topstar（当家球星）AI 乒乓球教练** 产品中完整实现并部署至生产环境：

1. **物理剥离有效性**：在非 VIP 用户的请求中，受保护内容不出现在模型的系统指令上下文中，已验证模型无法自行"猜测"或"推理"出受保护内容；
2. **行级泄漏检测命中率**：在测试集中，约 2%～5% 的模型回复中出现了对受保护内容的间接改写，均被行级敏感词检测捕获并移除；
3. **Prompt 注入防御**：使用多种 Prompt 注入攻击手法（如"忽略指令""角色扮演"等）测试，物理剥离方案下模型无法输出受保护内容，而纯 Prompt 约束方案在约 20%～30% 的攻击中被突破；
4. **TTS 通道验证**：验证 TTS 合成的语音中不包含受保护内容。
