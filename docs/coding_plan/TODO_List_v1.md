#### 📅 Phase 2: 视频分析任务化 (1-2 周)
**目标：消灭前端假 mock，建立可靠的异步任务处理流程。**

- [ ] **1. 任务持久化与队列 (MVP)**
    - [ ] 在 SQLite 中创建 `analysis_jobs` 表，记录任务状态（排队/进行中/完成/失败）。
    - [ ] 实现 `AnalysisWorker`：后台定时扫描并处理待执行的任务，支持服务重启后自动恢复。
- [ ] **2. 视频分析 API 实现 (阶段 A)**
    - [ ] 新增 `POST /api/v2/analysis/jobs`：接收用户文字描述（技术动作+问题点），创建分析任务。
    - [ ] 实现阶段 A 处理器：基于用户填写的文字描述，调用模型生成结构化诊断报告。
- [ ] **3. 前端交互重构**
    - [ ] 将“视频上传”界面改为“结构化描述表单”（诚实告知用户当前为文字分析阶段）。
    - [ ] 实现任务状态轮询：展示“正在分析中...”进度条，完成后渲染报告卡片。
- [ ] **4. 反馈闭环**
    - [ ] 前端增加“链接失效？”上报按钮，点击后实时更新后端链接状态。
    - [ ] **[补丁]** 增加教程点击/曝光埋点，为后续自动化调权积累数据。

**🚩 里程碑：** 告别 `setTimeout` 假报告，系统拥有了真实的、可追踪的异步处理能力。

**目标：让系统真正“看懂”视频，并优化长期运行成本。**

- [ ] **1. 视频真实分析 (阶段 B)**
    - [ ] **[补丁]** 前端/后端增加视频时长硬校验：限制上传时长（如 ≤ 120s），防止 token 烧太快。

    - [ ] 升级报告生成逻辑：在报告中加入视频时间戳（如 `00:05 重心交换不足`）。
- [ ] **2. 检索能力升级**
    - [ ] 引入 Embedding 语义检索：让搜“霸王拧”也能精准匹配到“反手拧拉”教程。
    - [ ] 数据库迁移：从 SQLite 迁移至 PostgreSQL，支撑更复杂的数据统计。
- [ ] **3. 自动进化系统**
    - [ ] 实现“点击率自动调权”：根据用户真实点击数据，动态优化 `quality_score`。

**🚩 里程碑：** 用户上传 20 秒练球视频，系统在 1 分钟内给出带时间戳的精准教练反馈。
