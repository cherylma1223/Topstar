# Phase 1 上线收尾清单（面向尽快发布）

说明：此清单只保留**影响正式发布上线**的收尾项，以及少量“上线后尽快补”的工作。  
原则：**能不做的先不做，先保证可发布、可排障、可持续同步教程数据。**

---

## 一、上线前必须完成

### 1. [发布稳定性] 补齐 v2 错误模型与 request_id

- [ ] **P1-S13** 为所有 `/api/v2/*` 接口统一错误响应结构：`code`、`retryable`、`request_id`
- [ ] **P1-S14** 为所有 v2 请求生成并透传 `request_id`，日志中至少记录：
  - 接口名
  - intent
  - 命中知识条目数
  - 命中教程数
  - 耗时
  - 错误码

目的：上线后用户报错时可以快速定位问题，避免出现“报错了但查不到是哪次请求”的情况。

### 2. [推荐质量] 修正教程推荐的候选召回/排序偏置

- [ ] 检查并修正 `recommendTutorials()` 的候选截断逻辑，避免“先截断、后排序”导致高相关教程进不了候选池
- [ ] 补充面向“动作本体教学”的排序信号，避免“反手拧拉怎么练”这类 query 被“拧拉后衔接 / 第二板 / 组合”主题的视频占满前 3
- [ ] 调整教程搜索标签构建逻辑，避免只依赖 `反手` / `拧拉` 这类粗粒度词命中，导致过多次主题内容混入候选池
- [ ] 为教程补充更细的主题标签或子类标记（如 `教学` / `练习` / `纠错` / `衔接` / `接发球场景`），不要仅靠 `action_id` 承担全部召回与排序语义
- [ ] 复核 `related_action_ids` 与教程主题的绑定质量，避免所有提到某动作的视频都被等权视为该动作的“直接教学视频”
- [ ] 回归验证以下场景：
  - 有 `action_id` 关联的教程优先于无关联教程
  - 问“反手拧拉如何练 / 怎么练”时，前 3 条优先返回动作本体教学，而不是“衔接 / 第二板”类视频
  - `status = 'dead'` 的教程绝不进入结果
  - 相同 query 多次请求时，结果稳定且可解释

目的：这是 Phase 1 的核心能力，推荐不稳定会直接影响首发体验。

### 3. [教程运维] 让教程同步链路可在正式环境运行

- [ ] 去掉 `syncTutorials.ts` 对本机绝对路径的强依赖，改为环境变量或明确的可配置路径
- [ ] 明确发布环境中的教程数据来源、同步频率、失败时的告警/回滚方式
- [ ] 至少完成一次“在非开发者本机环境可运行”的演练

目的：保证教程库不是“只能在当前机器上更新”，避免上线后数据无法持续维护。

### 4. [用户反馈闭环] 接通“链接失效”前端入口

- [ ] **P2-F4** 在 `AnalysisReportCard.tsx` 的教程视频区域增加“链接失效/打不开？”反馈按钮
- [ ] 前端调用已存在的 `POST /api/v2/tutorials/:tutorial_id/report-dead`
- [ ] 验证用户点击后，目标教程能被打到 `suspect` 状态，供 `linkHealthCheck.ts` 后续复核

目的：即使自动健康检查有漏网之鱼，用户也能帮助我们快速收敛死链问题。

### 5. [发布清理] 移除仍会误导用户的 mock 分支

- [ ] 清理当前前端里仍保留的 `setTimeout` 模拟报告分支
- [ ] 清理硬编码的 mock 视频链接，避免线上出现“真实教程系统已上线，但局部页面还在吐假链接/假报告”

目的：避免灰区逻辑混入正式环境，造成真假链路并存。

---

## 二、上线后尽快补（不是首发阻塞项）

### 6. [质量与维稳] 补齐意图评测基准

- [ ] **P1-S5** 创建 `intent_eval_set.jsonl`：补充约 30-50 条覆盖不同场景的业务测试用例
- [ ] 实现批量评测脚本，输出 intent 准确率与 action_id 命中情况

说明：这项很重要，但不会直接阻塞首发。现阶段先依赖人工回归测试。

### 7. [性能体验优化] 再评估意图路由延迟补偿

- [ ] 对 `v2/chat` 增加分类耗时监控，先量化真实延迟
- [ ] 若线上延迟明显，再考虑：
  - 后端增加高频 query 的短期缓存
  - 前端增加更友好的等待文案

说明：先监控，后优化；如果当前响应可接受，不提前做复杂缓存。

---

## 三、暂不纳入本轮发布

以下工作现阶段**不做**，避免分散资源：

- `chat_sessions` / `chat_messages` 持久化
- 更细的知识库模块拆分（`actions.ts` / `tactics.ts` / `equipment.ts`）
- 点击/曝光埋点与 `usage_events` 表
- 更完整的推荐质量自动调权
- Phase 2 的异步任务化 / Analysis Worker / 真实视频理解

这些内容统一在正式发布后，再按真实用户反馈决定优先级。

---

## 四、上线前最小验收清单

- [ ] 问“反手拧拉怎么练 / 给我视频教程”时，能稳定返回真实链接
- [ ] 模型回复中不出现任何自编链接
- [ ] 已知死链不会继续出现在推荐结果里
- [ ] 用户能手动反馈“链接失效”
- [ ] v2 接口报错时，日志里能通过 `request_id` 快速定位
- [ ] 教程同步链路可在正式环境独立运行
