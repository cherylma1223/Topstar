# Topstar 的 Agent Harness
## 把不可靠的大模型，变成可靠的乒乓球教练

> LLM 编排引擎 —— 确定性控制循环 × 领域特化护栏

---

# 一句话定义 Harness

> **Harness（编排 harness）= 确定性代码框架包裹非确定性模型调用**

通过六个控制环节，把「裸模型」变成「可控服务」：

```
约束输入 → 编排多步 → 校验输出 → 后处理 → 降级/重试 → 状态机管理
```

- 它**不训练**模型，也不**换**模型
- 它做的是：**管住**模型 —— 喂什么、怎么喂、喂完怎么收拾

---

# 为什么需要 Harness？

裸调大模型有三大不可控风险：

| 风险 | 表现 | Harness 的对策 |
|------|------|----------------|
| **非确定性** | 同一输入，输出漂移 | 低温度 + 模板/Schema 约束 |
| **幻觉** | 编造视频链接、编造动作名 | 白名单校验 + 知识库锚定 |
| **不可控** | 偶发超时/过载/模型下线 | 重试 + 模型降级 + 兜底 |

**一句话**：模型越强，越需要 harness 把它「按在轨道上」。

---

# Topstar 的 Harness 全景图

两条核心业务链路，共用同一套六职能 harness：

| | 对话链路 | 视频分析链路 |
|---|---|---|
| 核心文件 | `orchestrator/handleChatEvent.ts` | `orchestrator/handleAnalysisJob.ts` |
| 调度 | HTTP 即时响应 | `jobs/analysisWorker.ts` 轮询 Job |
| 结构 | 单轮：路由→检索→生成→校验 | 多轮：Pass1→1.5→2 级联 |

> 全部**手写、零依赖**，不借助任何通用 Agent 框架。

---

# 职能① 输入侧控制
### Input Gating / Context Assembly

模型开口前，先把「该说什么、不该说什么」焊死。

- **全局约束**：禁 Markdown，强制 `【标题】` 结构
- **意图模板**：按 6 种意图注入不同的输出结构
- **知识注入**：检索命中 → 拼进 system instruction
- **权限规则**：非 VIP 注入「绝对不许提及核心秘诀」

**商业价值**：从源头把「自由发挥」变成「按处方作答」，回答始终符合教练规范。

---

# 职能② 调用侧控制
### Retry / Fallback / 模型降级

把「模型失败」这件事消化在 harness 内部，对外永远给可用结果。

- **指数退避重试**：`withRetry` 处理 503/429/过载，最多 3 次
- **模型降级链**：`3.1-pro → 2.5-pro → 2.5-flash`，仅对 404 降级
- **意图三级兜底**：规则 → LLM → 默认意图，链路永不中断

**商业价值**：单点模型抖动不传导给用户，可用性从「看运气」变「有保障」。

---

# 职能③ 输出约束 + 校验
### Output Constraint / Validation

**不完全信任模型输出**，这是 harness 最克制的地方。

- **Schema 强约束**：`responseSchema` + JSON 强制结构化
- **反幻觉护栏**：`intent` / `action_id` 对候选集白名单校验，编造就丢弃
- **模板校验**：缺段落自动补 `暂无相关内容` 占位
- **JSON 兜底**：模型没乖乖输出 JSON 时正则提取降级

**商业价值**：把「生成式」变成「校验式」，报告格式 100% 稳定可解析。

---

# 职能④ 输出后处理
### Post-processing / Sanitization

模型答完，还要过最后一道「安全闸」。

- **VIP 脱敏**：段落级 + 行级剥离 `核心秘诀 / 二次点火` 等泄露词
- **锁区占位**：非 VIP 强制下发 `[LOCKED_VIP_CONTENT]` 供前端渲染锁区
- **问题去重**：规范化文本后合并重复诊断项

**商业价值**：付费内容物理隔离，会员权益与免费体验的边界由代码兜底，而非靠模型自觉。

---

# 职能⑤ 生命周期 / 状态机
### Lifecycle & State Machine

把一次调用抽象成**有状态、可恢复、可并发**的 Job。

- **状态流转**：`queued → running → done/failed`
- **原子抢占**：`UPDATE ... WHERE status='queued'` 防并发抢单
- **超时保护**：`Promise.race` 套 10 分钟硬超时
- **崩溃恢复**：重启后 `running → queued` 自动续跑

**商业价值**：海量视频分析任务可排队、可重试、可恢复，具备真正的工程级可靠性。

---

# 职能⑥ 可观测性
### Observability

Harness 不只「跑」，更要「能被追踪」。

- 全链路打点：`上传 → Pass1 → Pass1.5 → Pass2 → 清洗`
- 每个 request_id / job_id 串联完整生命周期
- 耗时、模型、降级状态全部落盘

**商业价值**：故障可定位到具体环节，也为未来「黄金回归测试集」沉淀埋点数据。

---

# 手写 Harness vs 通用框架

| 维度 | 手写 Harness（Topstar） | 通用框架（LangChain 等） |
|------|------------------------|--------------------------|
| 领域深度 | 乒乓球知识库 + 动作诊断规则深度内嵌 | 通用，需额外适配 |
| 可控性 | 每行代码可见、可改 | 黑盒抽象层 |
| 依赖 | 零额外依赖，启动轻 | 引入重依赖 |
| 复用性 | 低（单领域专用） | 高 |

> 不是「买不起框架」，而是**领域壁垒就藏在手写 harness 里**。

---

# 技术壁垒总结

Topstar 的护城河，一半在**知识库与多模态分析**，另一半就在这套 **Agent Harness**：

1. **确定性** —— 同一条视频，无论测多少次，结论一致
2. **防幻觉** —— 白名单 + 知识锚定 + Schema 三重护栏
3. **高可用** —— 重试、降级、兜底、崩溃恢复全链路兜底
4. **可审计** —— 每个输出都有据可查、有迹可循

> 大模型谁都能接，**把大模型驯成教练的 harness，才是壁垒**。
